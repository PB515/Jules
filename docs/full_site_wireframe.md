### Shell structure (`app/(node)/layout.tsx`)

There is **no persistent top header/app-bar anywhere in the student PWA**. Every screen renders its own inline "eyebrow + H1" (or just an H1) at the top of its own scrollable content — there is no shared, sticky title bar, no back button chrome, no global search. The only persistent chrome is a **bottom tab bar**.

Root container:
```
<div className="flex min-h-screen flex-1 flex-col bg-background">
  <main className="mx-auto flex w-full max-w-md flex-1 flex-col pb-20">{children}</main>
  <nav className="fixed inset-x-0 bottom-0 z-20 border-t border-border bg-card/95 backdrop-blur">
```
- The whole app is capped to `max-w-md` and centered (`mx-auto`) — a phone-width column even if viewed wider.
- `pb-20` on `<main>` exists specifically to keep content clear of the fixed bottom nav.
- Every individual screen then applies its own `px-5 pt-8` (or similar) padding inside that `<main>` — padding is NOT global, it's repeated per-page.

### Bottom tab bar (persistent, `< Icon >` + label, 5 items)

`< Icon: Home > Grid` · `< Icon: ScanLine > Scan` · `< Icon: MonitorPlay > Live` · `< Icon: Trophy > Records` · `< Icon: User > Profile`

Classes: `fixed inset-x-0 bottom-0 z-20 border-t border-border bg-card/95 backdrop-blur`, inner row `mx-auto flex max-w-md items-stretch justify-between px-2`. Each tab: `flex flex-1 flex-col items-center gap-1 py-2.5 text-tertiary transition-colors hover:text-gold` — icon `size-5` above a `text-[10px]` label. **No active-route highlighting exists on this bottom nav** (unlike the admin sidebar and public-site nav, which do have kumkum active-state highlighting per decision 40 — this bottom bar was never included in that pass).

### The two-layer PWA gate wraps everything, before any of the above renders

`app/(node)/pwa-gate.tsx` sits directly inside the layout, outside the `<div>`/`<nav>` shell — so its own three states are literally the only thing on screen until it resolves:

- **`checking`** (default/first paint): a bare full-viewport centered spinner, `< Icon: Loader2 >` (spinning), no copy, no logo — `flex min-h-screen items-center justify-center bg-background`. Deliberately blank/neutral so a real installed-PWA user never sees a "you need to install this" flash.
- **`blocked`** (confirmed not running standalone): renders `< PwaRequired >` (see below) instead of the tab-bar shell entirely.
- **`standalone`** (confirmed installed): wraps `children` (the whole `<div>`/nav shell above) in `< LaunchSplash >`.

**`PwaRequired` full-bleed screen** (`lib/components/pwa-required.tsx`) — shown by both this client gate and the server-side `proxy.ts` redirect for a non-mobile User-Agent, so a desktop visitor and a mobile-but-not-installed visitor see the identical screen:
```
main.flex.min-h-screen.flex-col.items-center.justify-center (full viewport, no nav)
  < Icon: Smartphone >  (size-10, gold)
  h1 "Synergy is built for your phone"
  p  "To keep quizzes fair and focused, one device, nothing else open..."
  [ Button: Get the app on your phone ]  → links to /get-app (public site, outside this shell)
```
No bottom tab bar, no other chrome — this is a dead-end screen with one exit.

**`LaunchSplash`** (once-per-calendar-day, `lib/components/launch-splash.tsx`) — a full-screen overlay (`fixed inset-0 z-50`, opaque `bg-background`) that sits ON TOP of the real dashboard/shell (which is already mounted underneath and rendering normally — this is cosmetic-only and fails open). Sequence, each phase replacing the last inside an `AnimatePresence mode="wait"`:
1. **jolt** (0–650ms): the app icon (`/icons/icon.svg`, `size-24`) springs in from `scale:0.3, rotate:-8deg` to full size.
2. **moto** (650–1550ms): the icon is replaced by centered moto text (`text-xl`, gold, `whitespace-pre-line`) — alternates day-to-day between the English tagline and a verbatim Gujarati verse.
3. **return** (1550–1950ms): the icon (`size-20`, slightly smaller) fades back in.
4. **exit** (1950–2250ms): the whole overlay fades to transparent, revealing the already-rendered shell underneath.

**`OnboardingTour`** (`lib/components/onboarding-tour.tsx`, once-per-account, only ever mounted inside `dashboard/page.tsx`) — a separate full-screen overlay (`fixed inset-0 z-40 bg-background/98 backdrop-blur-sm`) shown only on a brand-new account's first Dashboard visit, layered under the splash's `z-50` but above everything else:
```
< Icon: X > (top-right, dismiss/skip)
  centered icon-in-circle (size-16 rounded-full bg-card) + slide icon
  h2 slide title
  p  slide body
  • • • •  (4 dot-indicators, active dot gold)
[ Button: Next ]  (or "Get started" on the last of 4 slides)
```
4 fixed slides: Earn Joules → Scan to check in → Play Surges and Live Rounds → Climb the Leaderboard.

### [Dashboard ("Grid")] — /dashboard

**Header Area**: No app-bar. Inline greeting block at the very top of the scrollable column: `p` "Welcome back," (muted, small) + `h1` student's first name (`text-xl font-medium`). `OnboardingTour` and `TierUpCelebration` are mounted here but render nothing visually until/unless triggered (both are overlay components, not part of layout flow).

**Main Content Grid**: A single vertical column (`flex flex-col gap-6 px-5 pt-8`) of stacked full-width sections, no side-by-side grid anywhere except one internal 1-col/2-col split noted below:
1. Greeting block (name).
2. **{ Card: Season card }** — `rounded-2xl border bg-card p-6`, an "ambient-drift" background animation class. Inside:
   - Row: `p` "Season Joules" (eyebrow) + huge `< CountUp >` number (`text-4xl`, gold) on the left; `< TierBadge >` pill on the right (`flex items-start justify-between`).
   - A thin horizontal progress bar (`h-1.5 w-full rounded-full bg-background`, filled portion `bg-gold`, width = tier progress %).
   - Caption below: "N J to next tier" or "Top tier, uncapped".
   - A row: "Lifetime Joules" label (left) + `< CountUp >` value (right).
   - Conditional caption: "Season ends in N days".
   - `border-t border-border pt-4` divider, then "Streak" label + `< StreakChain >` visual (interlocking ring chain, see Global Shared Components note below).
3. **Power Grid section** — header row: "The Power Grid" (h2) left, "N logged" (tertiary) right. Below it, `< PowerGrid >`: a **5-column CSS grid** of 20 square cells (`grid grid-cols-5 gap-2`, each cell `aspect-square rounded-md border`) — lit cells solid gold, unlit cells are empty bordered squares. This is the one genuine grid layout on this screen.
4. **[ Button: Scan event QR ]** — full-width, gold background, centered icon+label, links to `/scan`.
5. **Reminders section** (only rendered if any exist) — h2 "Reminders" + a bordered card list (`divide-y divide-border rounded border bg-card`), each row a `< Icon: Bell >` (gold) + message text, linking to the relevant event.
6. **Upcoming events section** — h2 + either `< EmptyState >` (icon Calendar, "Nothing on the calendar yet") or a divided list of rows (event name truncated + date/time sub-line, accent-colored time) with a right-aligned "Registered" or "View & register" label + chevron.
7. **My registered events section** — same list shape, right-aligned status pill: "Attended" (success/CircleCheck), "Missed" (accent/CircleX), or "Registered" (muted/Clock).
8. **Recent activity section** — h2 + either `< EmptyState >` (icon Clock, "No sparks yet") or a divided list: activity label (or "Your first spark ⚡" for the chronologically-first-ever transaction) + timestamp on the left, `±N J` (gold if positive, accent if negative) on the right.

**Interactive Modals/Drawers**: None on this screen itself. Two full-screen overlay components can appear on top (not modals in the dialog sense): `OnboardingTour` (first-ever visit only) and `TierUpCelebration` (fires only on a detected tier promotion since the last visit — a `fixed inset-x-0 top-6 z-40` banner near the top of the viewport, not a full overlay, showing a `WinnerBurst`-wrapped card: "You reached" + `TierBadge` + "{Tier} unlocked", with confetti/sound/vibration).

**State Changes**:
- *Loading*: this is a Server Component — the whole page blocks server-side on 7 parallel Supabase calls before first paint; there is no client-side skeleton/spinner state for the page shell itself.
- *Empty*: "Upcoming events" → `EmptyState` "Nothing on the calendar yet"; "My registered events" → `EmptyState` "No registrations yet" / "Register for an upcoming event above."; "Recent activity" → `EmptyState` "No sparks yet" / "Scan into an event or join a Surge to start generating Joules."
- *Success/realtime*: none of this page's data is realtime-subscribed — it's a fresh server render per navigation; the "Season Joules"/"Lifetime Joules" numbers animate via `CountUp` (count from 0 to the fetched value over ~700ms) on every mount, not just on change.
- *Error*: no explicit error UI on this page — a failed Supabase call would surface as an unhandled server error, not a designed error state.

### [Scan] — /scan

**Header Area**: Inline `h1` "Scan event QR" at the top of the column (`px-5 pt-8`), no other chrome.

**Main Content Grid**: Single vertical column, `flex flex-col gap-6`, then the client component's own `flex flex-col gap-5`. Three stacked blocks depending on state (never side-by-side):
1. **{ Card: camera prompt }** (default idle state) — centered column, dashed-free bordered card (`rounded-2xl border bg-card p-8 text-center`): `< Icon: ScanLine >` (size-10, tertiary), instruction text, then **[ Button: Scan with camera ]** (gold, icon `< Icon: Camera >`).
2. Inline error banner (only if a redemption attempt failed) — `rounded border-accent/40 bg-card p-3`, `< Icon: CircleX >` + friendly message.
3. **{ Card: manual check-in }** — bordered card, eyebrow "Or check in manually", then a vertical stack: `[[ Input: Select event… ]]` (native `<select>`, `.input` class), `[[ Input: 10-character code ]]` (text, uppercased, maxlength 10), **[ Button: Check in ]** (full-width gold, disabled until both fields filled, label swaps to "Checking in…" while pending).

**Interactive Modals/Drawers**: The **camera scanner is a full in-place view swap, not a modal** — tapping "Scan with camera" replaces the entire content column with `< CameraScanner >`:
```
relative rounded-2xl border bg-black
  <video> (aspect-square, object-cover, live camera feed)
  a centered inset-8 gold-bordered square overlay (scan target guide)
p  "Point your camera at the event's QR code." (or an error message in the accent-colored banner style)
[ Button: Cancel ]  (outlined, full-width, returns to the idle view)
```
Camera permission errors render inline in place of the guide caption (denied / no camera / generic failure), all still inside this same view — no separate error modal.

**State Changes**:
- *Idle*: the two-block idle view above (camera prompt + manual form).
- *Loading ("redeeming")*: the manual Check-in button's label changes to "Checking in…" and disables; there's no full-page spinner/skeleton — the rest of the UI stays interactive-looking but the button is the only visible feedback.
- *Success*: **the entire screen is replaced** by a single centered success card (`rounded-2xl border-success/40 bg-card p-8 text-center`): `< Icon: CircleCheck >` (success green), big `+N J` (gold), "Credited to your Grid" caption, a `< TierBadge >`, and — conditionally — a small tertiary note "Flagged for admin review (location check), your Joules are still credited." No further action/button; the student must use the bottom nav to leave.
- *Error*: inline accent-colored banner (`< Icon: CircleX >` + message) appended below whichever view (idle or camera) was active — friendly-mapped messages for "already credited," "not open for check-in," "invalid or expired code," "event not found," and a generic fallback.
- *Empty*: if no events are open for manual check-in, the manual-form card shows just `p` "No events are open for check-in right now." in place of the select/input/button.

### [Live Round — Play] — /live/[roundId]

This single route renders **two structurally different screens** depending on whether the student has joined a team yet, and — once joined — **five distinct phase-states** driven live by Supabase Realtime on `live_rounds.phase`. All of it renders inside a full-bleed `<main>` (`flex flex-1 flex-col ... px-6 py-8` for the play screen, centered `items-center justify-center` for team formation), no bottom-tab-bar-relative content padding beyond the shared shell.

#### Sub-state A — Team formation (no team yet, round still in `lobby` phase)

**Header Area**: none; centered column.
**Main Content Grid**: single column, `max-w-xs`, centered:
1. Small row: `< Icon: Users >` (gold) + "Room {code}".
2. `p` "Team up with classmates, or play solo." + smaller tertiary explainer: "Whoever starts a team is its captain and answers for everyone. Other members share the team's points but don't answer themselves."
3. **Open teams list** (only if any exist) — bordered/divided card, each row: team name + "(N joined)" tertiary, right-aligned **[ Button: Join ]** (small pill, gold).
4. Two mutually-exclusive action blocks:
   - Default: **[ Button: Go solo ]** (full-width gold — auto-creates a 1-person team named after the student) stacked above **[ Button: + Start a team ]** (dashed-border outline, opens the create form).
   - Create form (toggled): **{ Card }** with `[[ Input: Team name ]]` + side-by-side **[ Button: Create ]** (gold, disabled until non-empty) / **[ Button: Cancel ]** (outline).

**Interactive Modals/Drawers**: The create-team form is an inline expand/collapse within the same column, not a true modal/drawer.

**State Changes**: *Empty* (no open teams) → the open-teams list block simply doesn't render, straight to the Go-solo/Start-a-team buttons. *Loading* → the pressed button's label swaps ("Creating…"/"Joining…") and all buttons in the block disable. *Error* → plain accent text line above the buttons.

#### Sub-state B — Team play (has a team; the round's live phases)

Persistent element across every phase: a top strip, `flex items-center justify-between text-xs` — "Team: {teamName}" (accent color) on the left, "+N J per correct answer" (gold) on the right. Below that, exactly one of the following renders at a time, swapped live by the realtime subscription (no client-side routing, same URL throughout):

**1. `lobby` phase** (joined, waiting for host to start):
Centered column: "You're in!" (large), "Waiting for the host to start the round…" (tertiary), and **[ Button: Not your team? Leave ]** (plain underlined text button) — calls `leave_live_team`, bounces back to Sub-state A.

**2. `question` phase — precise layout**:
- `< EnergyBar >` full-width decaying bar (h-2, rounded-full) — NOT a numeric countdown, a pure horizontal bar that shrinks left-to-right and shifts color gold → amber → kumkum-accent as time runs low, jittering under 20% remaining.
- `h2` question text (`text-lg leading-snug font-medium`), full width, directly below the bar.
- If the viewer is not the team captain: one line of centered tertiary text, "Your team captain is answering for the team."
- **Answer options are a single-column vertical stack, never a 2×2 grid** — `flex flex-1 flex-col gap-3`, each option a full-width button (`flex items-center justify-between rounded-[var(--radius)] border px-4 py-3.5`), all four buttons identical height/width, stacked A/B/C/D top to bottom, each prefixed with its own letter (`A.` etc. in tertiary color) then the option label. Only the currently-selected option gets visual distinction (gold border + `--tier-volt-bg` background fill) — the other three stay neutral (`--border`/`--card`) until reveal. Non-captains see the whole stack at 60% opacity and cannot tap (disabled).
- Once the captain has picked one: centered tertiary text "Locked in, waiting for the host…" appears below the stack — **no correctness feedback of any kind is shown yet**, regardless of whether the pick was right or wrong (this was a deliberately-fixed bug — see decision 73 in project history).

**3. `reveal` phase — precise layout, two variants**:
- **Suspense variant** (only on milestone questions: halfway/three-quarter/final on 8+ question rounds, always on the final question of any round): the entire question/options area is replaced by a centered `flex-1` block — a single pulsing gold line "Revealing the answer…" plus the milestone caption ("Halfway there" / "Final stretch" / "Final question") beneath it, for ~6.5s (synced to a drumroll sound + a building vibration pattern). No options are visible during this window.
- **Standard reveal** (after the suspense window, or immediately on a non-milestone question): same `h2` question text at top, same vertical single-column button stack as the question phase — but now every option is color-coded simultaneously: the correct option gets a `--success` (green) border + a `< Icon: Check >` on the right; the team's own wrong pick (if any) gets a `--accent` (kumkum/danger) border + `--tier-current-bg` fill + a `< Icon: X >`; everything else stays neutral. Below the stack, one centered line: `+N J!` (success-colored) or "Not quite." (accent-colored) — this is the first moment correctness is revealed to the student, gated on the host's actual "Reveal" click, not on submission.

**4. `leaderboard` phase** (shown after every non-final question, and after the final question before the host clicks "Finish round"):
`h2` "Scoreboard" + a vertical list (`flex flex-col gap-2`) of every team, each row a full-width bordered pill: rank number (or a `< Icon: Crown >` for rank 1) + team name on the left, `N J` (gold) on the right. The viewing team's own row is highlighted (gold border + `--tier-volt-bg` fill); all others neutral. Deliberately understated — no confetti/sound here, even for the team currently in 1st, since this isn't the true final result.

**5. `complete` phase** (the round has genuinely ended):
`h2` "Final standings" + `< RevealScoreboard >` — the same row visual as the leaderboard list above, but **staggered-reveal, worst-rank-to-best** (~370ms apart), with rank 1 arriving last inside a `< WinnerBurst >` wrapper (confetti fired from that row's own screen position + a distinct sound + a vibration pattern). Below the scoreboard: two stacked full-width buttons — **[ Button: View Leaderboard ]** (gold, `< Icon: Trophy >`, → `/leaderboard`) and **[ Button: Back to Grid ]** (outline, `< Icon: Home >`, → `/dashboard`).

**Interactive Modals/Drawers**: none — every transition above is an in-place content swap driven by realtime state, not a dialog/drawer.

**State Changes**:
- *Loading*: "Loading question…" centered text shown whenever `phase` is `question`/`reveal` but the question payload hasn't arrived from its own RPC call yet (a brief gap on every phase transition).
- *Realtime update*: every phase transition (`lobby→question→reveal→leaderboard→[question…]→complete`) is pushed via a Postgres-changes subscription on `live_rounds`; the client re-fetches the question/scoreboard RPCs reactively — no manual refresh ever required, including a cold page load landing mid-round (an explicit fetch-on-mount covers that case).
- *Error*: leaving a team surfaces a plain accent-colored line of text in the lobby view; there's no other explicit error state on this screen (answer-submission errors are silently swallowed client-side, matching the pattern in the code).

### [Surge (async quiz)] — /surge/[surgeId]

This route also branches hard on state, all inside the standard `px-5 pt-8` column (not full-bleed like Live Round).

#### Sub-state A — Surge not found
`< EmptyState >` only: icon `Zap`, title "Surge not found".

#### Sub-state B — Draft (registration open, not yet live)
**Header Area**: none beyond the EmptyState block itself.
**Main Content Grid**: vertical stack:
1. `< EmptyState >` (icon `Zap`, title "Not live yet", message "This Surge hasn't started. Check back when it goes live.").
2. **{ Card: group registration }** (`< GroupRegistrationClient >`) — two mutually exclusive views:
   - **Not in a group**: `p` "Playing solo right now. Team up, or just wait here." + open-groups list (name, "(N joined)", **[ Button: Join ]** pill) + **[ Button: + Start a group ]** (dashed outline) which expands into `[[ Input: Group name ]]` + Create/Cancel pair — visually identical pattern to Live Round's team-formation card.
   - **Already in a group**: gold-bordered card showing the group name, a comma-joined list of member names, and **[ Button: Leave group ]** (outline).

#### Sub-state C — Already answered everything
`< EmptyState >` (icon `Zap`, "Already answered", "You've completed every question in this Surge. Results land once it closes.").

#### Sub-state D — Live quiz play (`< SurgeClient >`) — precise layout
- Top strip: `flex items-center justify-between text-xs` — "Question X / Y" (tertiary) left, running total `±N J so far` (gold/accent) right.
- `< EnergyBar >` (same decaying horizontal bar component as Live Round, remounted fresh per question via a `key`).
- `h2` question text.
- **Vertical single-column stack of 4 option buttons**, identical shape/sizing to Live Round's — but here correctness color-codes **immediately and locally** the instant the student taps an option (no separate host-controlled reveal phase; this is self-paced): the chosen option locks, the correct option turns success-green with a Check icon, a wrong pick turns accent/kumkum with an X icon, then the whole quiz auto-advances to the next question after ~1.1s.
- Below the stack: "Time's up" (if the timer expired unanswered) or `±N J` (colored success/accent) once revealed.
- On the last question, auto-advances to `/surge/[surgeId]/matrix` instead of a next question.

**Interactive Modals/Drawers**: none anywhere on this route.

**State Changes**:
- *Empty*: no open groups → the open-groups list block just doesn't render (straight to solo copy + Start-a-group button); no questions available is structurally impossible here (surge wouldn't be playable).
- *Loading*: group actions show inline pending labels ("Creating…"/"Joining…"/"Leaving…"); quiz answers auto-lock the moment tapped, no separate spinner.
- *Error*: group actions show plain accent text above the action buttons.
- *Success*: reaching the last question redirects into the Matrix screen below.

### [Surge Matrix (results)] — /surge/[surgeId]/matrix

**Main Content Grid**: single vertical column.
- If the surge isn't found: `< EmptyState >` (icon Trophy, "Surge not found").

**State Changes**:
- *Empty*: `< EmptyState >` (icon Trophy, "No answers were recorded", "Nobody answered a question in this Surge yet.") in place of the ranked list, if literally nobody answered anything.
- *Loading*: N/A — this is a static, already-closed dataset; the only "loading" is the staggered reveal animation itself (skipped instantly under reduced-motion, showing everything at once).
- *Success*: the personal result card, described above.

### [Catalyst Records] — /catalyst

**Header Area**: eyebrow `p` "Permanent archive" + `h1` "Catalyst Records", inline at the top of the `px-5 pt-8` column.

**Main Content Grid**: single vertical column.
1. **`< SeasonPicker >`** — a plain native `<select>` styled with `.input` — **only rendered at all if 2+ seasons each have real recorded activity**; with the typical single-active-season case, this control is entirely absent (not a disabled/empty dropdown).

### Shared component notes (referenced across multiple screens above)

- **`< CountUp >`** — any large stat number (Season/Lifetime Joules) animates counting up from 0 over ~700ms on every mount (ease-out cubic), snapping instantly under reduced-motion. Purely a number-formatting/animation wrapper, no visual chrome of its own.
- **`< TierBadge >`** — a small pill (`rounded-full border px-3 py-1`), tier-specific icon (Flame/Zap/Award/Sparkles for Ember/Volt/Current/Plasma) + tier label text, colored entirely from `--tier-{tier}-{text,border,bg}` tokens; the Plasma variant gets a continuous subtle pulse animation class.
- **`< StreakChain >`** — a row of 1–6 overlapping rounded-rect "rings" (alternating tall/wide, overlapping via negative margin to read as an interlocking chain), solid gold when streak > 0, a single dashed/muted ring when streak = 0, always paired with real text ("N events in a row" / "No streak yet") so the count is never conveyed by the visual alone.
- **`< PowerGrid >`** — the only true CSS-grid layout in the student PWA: a fixed 5-column, 4-row (20-cell) grid of small squares, lit (solid gold) vs. unlit (bordered/empty) representing logged activity count.
- **`< EnergyBar >`** — a single thin horizontal bar (not a numeric countdown), decaying left-to-right over the question's time limit, recoloring gold→amber→kumkum as it depletes and jittering in the final 20%.
- **`< EmptyState >`** — the universal "nothing here" pattern used everywhere above: a dashed-bordered box, centered icon (40%-opacity) + title + optional message + optional action, `rounded-lg border-dashed p-10 text-center`.
- **`< WinnerBurst >` / `< RevealScoreboard >`** — the shared "true final result" treatment (confetti + sound + vibration + a spring pop) reused identically across Live Round's team screen, Live Round's host screen (out of scope here), and the Surge Matrix — ensures the "big moment" always looks/feels the same regardless of which quiz mode produced it.

### Shell structure

The Admin/Staff PWA ("Reactor Command Center") is a two-region shell defined in `app/admin/(protected)/layout.tsx`, wrapping every route under `app/admin/(protected)/*`. It is a classic **desktop sidebar + mobile top-bar** responsive split, with no shared header/footer chrome beyond these two regions — each page's own content starts immediately below.

Root container: `<div className="flex min-h-screen flex-1 bg-background">`

**Desktop sidebar** (`<aside className="hidden w-56 shrink-0 flex-col border-r border-border bg-card sm:flex">`) — hidden below the `sm:` breakpoint, a fixed 224px-wide (`w-56`) column, full viewport height, right-bordered, card-colored background. Three stacked zones inside it:
1. Brand header (`border-b border-border px-5 py-5`): `< Icon: none >` — just text — `{ eyebrow: "Synergy" (uppercase, tracked) }` over `{ title: "Reactor Command Center" }`.
2. Nav list (`<AdminNav>`, `className="flex flex-1 flex-col gap-1 p-3"`) — fills remaining vertical space.
3. Footer (`border-t border-border p-3`): admin identity line ("{name} · {role}") + `[ Button: Log out ]` (a form-submit button with `< Icon: LogOut >`, full-width, `hover:bg-background`).

**Mobile header** (`<header className="relative flex items-center justify-between border-b border-border bg-card px-4 py-3 sm:hidden">`) — shown only below `sm:`, replacing the sidebar entirely. Left side: `[ Button: <Icon: Menu/X> ]` (`MobileAdminNav` hamburger toggle, `size-11` tap target) + title text "Reactor Command Center". Right side: `[ Button: Log out ]` (plain text button, no icon, no border).

**Mobile nav drawer** (`MobileAdminNav`, only rendered when hamburger is tapped open): `<nav className="absolute inset-x-0 top-full z-20 flex flex-col gap-1 border-b border-border bg-card p-3 shadow-lg">` — a full-width dropdown panel anchored under the header, `min-h-11` tap targets per row, closes itself (`setOpen(false)`) on any link click. Reuses the identical `NAV` array and role filter as the desktop sidebar — not a second nav definition.

**Main content region**: `<main className="flex-1 overflow-x-hidden">{children}</main>` — no max-width or padding applied at the shell level; every individual page sets its own `mx-auto max-w-*` container and padding.

There is no sticky positioning anywhere in the shell (no `sticky`/`fixed` on the sidebar, header, or main) except the mobile nav drawer's `absolute` dropdown itself, which is positioned relative to the header, not the viewport.

Applies to literally every route in the app, not just this scope. `<html lang="en" className="h-full antialiased">`, `<body className="min-h-full flex flex-col bg-background text-foreground font-body">`.
